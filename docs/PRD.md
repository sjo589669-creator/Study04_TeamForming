# PRD: 팀 프로젝트 팀 편성 웹 앱

## 1. 목적
수강생(가상 학생)이 팀 프로젝트의 팀을 스스로 편성한다. 지원과 팀원 투표로 팀을 만들고, 모집 마감 뒤 남은 학생은 AI가 배정안을 내며, 앱이 그 배정안을 규칙으로 검사한 뒤 관리자가 확정한다.

## 2. 사용자
| 사용자 | 하는 일 |
|---|---|
| 학생 | 학번·비밀번호(1234)로 로그인, 팀 목록과 팀원의 주·보조 역할 보기, 팀에 지원, 내 팀에 들어온 지원에 찬성·거부 |
| 관리자 | 학번 `admin` 으로 로그인, 명단 CSV와 팀 수로 처음 상태 만들기, 모집 마감, AI 배정, 배정안 확정 |

## 3. 규칙
- 역할 6개: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자. 학생마다 주 역할 1개, 보조 역할 0~2개(명단에서 정함, 바꿀 수 없음)
- 팀 인원: 확정 뒤 모든 팀 2~4명
- 주 역할 중복 금지: 한 팀에 주 역할이 같은 학생이 2명 이상이면 안 됨
- 필수 포함 역할: 모든 팀에 기획자와 웹 프로그래머가 서로 다른 학생으로 1명씩(주 역할이나 보조 역할로 맡을 수 있음)

## 4. 기능 요구사항
### 4.1 지원과 투표
- 빈 팀에 지원하면 바로 승인
- 팀원이 있는 팀에 지원하면 대기. 투표하는 때의 팀원 모두가 찬성하면 승인, 한 명이라도 거부하면 바로 거절
- 막힘(지원을 접수하지 않음): 팀이 꽉 참, 같은 주 역할의 팀원이 있음, 이미 팀이 있음, 결과를 기다리는 지원이 있음, 모집이 마감됨, 필수 포함 역할을 맡을 학생의 자리가 모자람
- 승인 직전 재검사: 모든 팀원이 찬성한 순간 정원·주 역할 중복·필수 포함 역할 자리를 다시 검사하고, 어기면 거절
- 투표는 바꿀 수 없음. 이미 투표한 지원은 "내 투표: 찬성"처럼 보여 주고 단추를 숨김

### 4.2 마감과 배정
- 마감: 대기 중인 지원은 거절, 1명뿐인 팀의 학생은 팀에서 빠짐
- AI 배정: 오픈라우터 텍스트 생성 모델 1차→2차→3차. 모델마다 전체 120초 제한. 응답 없음·빈 응답·오류·검사 탈락이면 다음 모델
- 배정안 검사 5가지: 빠짐없이 배정, 한 학생 한 팀, 모든 팀 2~4명, 주 역할 중복 없음, 필수 포함 역할 충족
- 3차까지 실패하면 앱이 모든 경우를 따져 규칙을 지키는 배정을 찾음
- 규칙을 지키는 배정이 아예 없으면 AI를 부르지 않고 "규칙을 지키는 배정이 없음"과 이유를 보여 줌
- 검사를 통과한 배정안만 관리자에게 보여 주고, 확정하면 DB에 저장

### 4.3 화면
- 공고 2.7절의 Streamlit key 를 그대로 씀(login_student_no, result, team_1, apply_1, vote_yes_{학번} …)
- 결과 안내는 "승인/대기/거절/막힘"으로 시작
- 다른 사람의 변경은 `st.fragment(run_every=3)` 로 3초마다 그 부분만 다시 그림
- AI 대기 중에는 몇 차 모델을 몇 초째 기다리는지 보여 줌

## 5. 비기능 요구사항
- 비밀번호는 bcrypt 해시로 저장
- 오픈라우터 키, DB 주소, 관리자 비밀번호는 `.env`(로컬)와 Streamlit Secrets(배포)에만 둠. 화면·로그에 출력하지 않음
- 테이블 이름은 모두 `tf_` 로 시작, `schema.sql` 로 남김
- DB 연결은 연결 풀로 한 번 만들어 다시 씀
- 마지막 자리 경쟁은 `tf_members` 의 유일성 제약으로 먼저 도착한 학생만 기록
- Supabase 일시정지 방지: GitHub Actions 예약 작업으로 매일 DB에 질의

## 6. 범위 밖
